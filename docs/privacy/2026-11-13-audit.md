# GRIDS privacy, analytics and infrastructure audit

Audit date: 2026-11-13 (Asia/Seoul). Status: **technical audit substantially completed; Google/EmailJS/mailbox account review and final publication remain pending**.

This is a factual implementation audit and a proposed legal-basis assessment, not a certification of compliance. Findings distinguish source inspection, anonymous live-browser observation, published provider configuration, authenticated read-only Vercel API evidence, provider documentation and owner decisions. No tags or provider settings were changed, no real inquiry was sent, no visitor logs were downloaded, and no deployment was performed.

- Live requests also reached `stats.g.doubleclick.net/g/collect` and `www.google.co.kr/ads/ga-audiences`, with `npa=0`. Advertising/audience-related endpoints are actually contacted. Do not describe remarketing as disabled merely because no `AW-*` tag was found.
- The app loads GTM before interaction in production (`src/app/layout.tsx`), including a no-JavaScript iframe fallback. No CMP, consent-default/update calls, reject control or withdrawal control was found.
- Live Google consent state: `active=false`; `analytics_storage`, `ad_storage`, `ad_user_data`, `ad_personalization` all reported implicit true. This is **not** recorded affirmative consent. Observed requests included `gcd=13l3l3l3l1l1`, no `gcs`, and `npa=0`.
- No site-specific opt-out exists today. Required remediation before describing opt-in/withdrawal: agree a purpose-specific consent design; block optional tags until allowed; add equally accessible rejection and withdrawal; test before choice, reject, allow, withdraw, reload and route change. Consent Mode alone is not a consent interface, and denied-mode cookieless requests are not equivalent to no third-party contact.
- Decide whether automatic user-provided-data collection is actually needed. Prefer disabling it in the Google tag for ordinary inquiry analytics unless a separate, documented use and basis have been approved. No Google account setting was changed by this audit.

## C3. Cookies and identifiers

Clean desktop Chrome observations; browser limits and renewed visits can change expiry. Values/client identifiers were deliberately not retained in the evidence.

| Item | Purpose and scope | Observed duration | Actual removal / opt-out today |
| --- | --- | --- | --- |
| `_ga` | GA user/browser distinction; first-party cookie on `.gridsagency.com`, `/` | About **400 days** in the tested Chrome browser | Clear/block this site's cookies. This clears that cookie but does not by itself block future Google requests or recreation. No site withdrawal control exists. |
| `_ga_4TFWB7JM6W` | GA session state; same parent-domain scope | About **400 days** in tested Chrome | Same limitation. Scope includes eligible GRIDS subdomains, including demo hosts. |
| `cid`, `sid`, page/referrer URLs, timestamps, device/browser/language/screen fields | Google request identifiers and event metadata | Request parameters; Google's server retention not verified | Blocking collection requires a functioning site control or an effective client-side network blocker; deleting browser cookies does not delete server-side records. |
| `localStorage.theme` | Forced light-theme preference, local browser | No application expiry | Clear site storage; not an analytics opt-out. |
| `sessionStorage['grids:site-visited']` | Prevent repeated homepage loading animation | Browser tab/session | Close the session or clear session storage; not an analytics opt-out. |
| Connect draft | React component state, not persistent storage | Until form unmount/reload/navigation; success alone does not clear the draft | Close/reset the form or leave/reload. It is not written to localStorage/sessionStorage. |

Google's documented default GA cookie lifetime is two years; Chrome caps first-party cookies at 400 days and Safari may apply a shorter limit. Do not publish "all data is deleted after 400 days" or equate cookies with GA server retention. No `_gcl_*` cookie was observed in these ordinary, non-ad-click sessions; ad-click and signed-in/regional variants were not exercised.

The Google Analytics opt-out browser add-on is a limited external GA option for supported browsers. It is not a universal mobile/Ads opt-out or a server-data deletion request. Google My Ad Center changes ad personalization and is not an opt-out from all measurement. Browser cookie blocking alone can leave cookieless requests active.

## D1. Form necessity, purposes and rights

- **Reply email** is necessary for the requested reply. A **contact name** helps address/identify the inquiry; do not require a verified legal identity merely to ask a question.
- **Service selection** helps route the requested inquiry; the form accepts an "unsure" choice. This is proportionate to the current flow.
- **Budget selection** helps quoting, but necessity for *every* initial inquiry is not established. The existing "not sure/no fixed budget" choices reduce friction, yet a genuinely optional budget is preferable for minimization. This audit does not silently alter the form's validation.
- **Company/team and notes** are optional. Conditional other-details text is required only if the visitor selects Other. Do not ask for sensitive personal information in free text.
- PIPA 15(1)(4) can support processing necessary to take steps requested during contract formation. This is a candidate basis for the business inquiry, **not** automatic authorization for analytics/advertising, mailing lists or all optional data. Optional fields used solely to answer a submitted request still require a documented purpose/necessity assessment.
- No newsletter/marketing subscription is implemented in the active form. Do not add a mandatory blanket terms/privacy consent checkbox and treat it as consent to every purpose. If marketing, Ads audiences, enhanced user data or another optional purpose is adopted, obtain the appropriate separate choice/basis and keep evidence.
- Privacy contact confirmed: `kyle@gridsagency.com`. The proposed rights process covers access, correction, deletion, processing restriction and consent withdrawal where applicable, with proportionate identity checks and documented lawful exceptions. It must not require collecting government ID by default.
- No operational request register existed in the repository. The accompanying operations document supplies the process/template; it is not evidence of historic handling or automatic provider deletion.

## D2. Verified security claims and gaps

**Verified:** valid HTTPS on the live site, HSTS `max-age=63072000`, HTTPS EmailJS API path in the SDK, one Vercel OWNER role, verified custom domains, Vercel authentication configured for non-custom-domain deployments, no external log drains returned, and no persistent browser inquiry draft in application code.

**Material gap:** the sole Vercel team member returns `mfaEnabled=false`. Do not publish "MFA is enforced". Enabling MFA requires the account owner; no account setting was changed.

**Not verified:** Google/EmailJS/mailbox MFA, recovery/admin access, shared mailboxes/forwarding, device protection, at-rest encryption of inquiry storage, access review cadence, backups, deletion propagation, incident process, accepted processor terms, or CAPTCHA/domain restrictions. Provider descriptions of their own controls are not evidence GRIDS has configured them.

**Additional observations:** no CSP, X-Content-Type-Options, Referrer-Policy or frame-ancestors header was present in the captured main response. These are hardening items for review, not proof of an exploit. Avoid a blanket "all security measures implemented" statement. Client validation is not a server security boundary. No attack, scanning or login attempt was performed.
